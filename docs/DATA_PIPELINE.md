# 数据生产与质量

本文合并说明采集器、任务执行、完整性审计和数据查询治理。

**读运营总览时注意三个口径**：历史未齐日期里的“证券日”按某证券在某日是否有记录统计，
不是请求数，也不证明筹码价格档位完整。估值分布的五项计数、中位数即使与独立 SQL
一致，只能说明有效样本的数值正确；成员缺行、源字段缺值、被规则排除的值分别留证，
不以零补缺。后续周期的蚂蚁快照即使成功，也不回补上一周期的历史快照。

交易日 18:58 另查已经滑出最近七天窗口的待确认空结果，只匹配日级
`recheck_empty`，通过任务的输出数据集找到采集任务，每次最多追加 16 个低优先级
历史实例。同范围已有活动实例或已有逾期复查的不再新建；失败须先核对请求与业务表。

**升级审计口径**时，日历和覆盖明细把旧版结果显示为待复核，不因旧任务成功而继续算绿。
调度器从当前分区及其来源审计发现过期日期（包括没有 coverage job 的 V2 审计），
按数据集和月份提交只读业务表的审计，队列最多补到 4 个。新规则证实日级缺口后，
同范围旧版就绪凭证会被撤销；原执行、原验收事件和新审计 ID 均保留。范围补采继续遵守交易时段限制。

## 一个实例的边界

一个 `task_execution` 对应一个可独立验收的逻辑周期：交易日、自然周、自然月、报告期
或快照。分页、日期窗口收缩、证券/市场枚举都在 `acquire` 节点内部完成，不拆成调度层
叶任务。

采集任务固定包含：

1. `condition`：判断交易日、发布时间和运行条件；
2. `scope_plan`：冻结业务日期、分区、请求参数和幂等身份；
3. `acquire`：穷尽分页/范围、幂等落库并保存请求证据；
4. `validate`：独立审计业务表、实体覆盖和传输完整性；
5. `publish`：验证通过后发布数据集状态。

派生任务使用 `condition → dependencies → scope_plan → transform → validate → publish`，
只读取已发布为 ready 的输入状态，不访问上游。输入状态版本会冻结到实例中；上游修复
重新发布后会产生新的可追溯派生实例。

## 控制面

`orchestration_v2` 使用五张表：

| 表 | 职责 |
|---|---|
| `acquisition_endpoint` | 来源 Endpoint 契约、handler 引用和凭据引用 |
| `task_definition` | 草稿、生效版本和历史版本 |
| `task_execution` | 实例范围、节点状态、租约、重试和最终错误 |
| `task_execution_event` | 追加式节点、请求、验证和状态证据 |
| `dataset_state` | 按数据日期/报告期发布的严格数据状态 |

Scheduler 只创建实例，不直接调用上游。例行、历史修复和派生任务使用独立资源池；历史
资源池在交易日 08:30–16:00 不领取新任务，避免与盘中日常采集争抢资源。

2026-10-30 治理：采集 acquire 在每个请求边界重新检查交易时间，已完成请求保留
检查点，以无失败延期返回队列，不消耗尝试次数。单个采集器调用内部的分页与长计算
尚不能在任意位置暂停，因此这是安全边界让出，不是强杀正在进行的数据库写入。
全市场本地因子任务领取增加跨日常/历史资源池互斥；已运行实例不会被抢占。
全数据集覆盖审计只在20:30投放，取消09:30开盘投放；日常任务独立校验不受影响。

控制台任务中心以“来源 → 定义与节点 → 最近10次实例 → 实例发布的数据验收”关联展示。
任务定义可按来源筛选；数据来源目录里的任务链接进入任务定义，实例可返回其确切
版本的定义。最近实例包括旧版本，验收证据只代表对应实例范围，不是全历史就绪证明。
关联查询不读取业务大表，不返回凭据；最多展示200条发布证据，截断显式提示。

生产恢复会记录当前正在运行的服务并停止除PostgreSQL之外的服务（包括派生、盘中、
历史因子和备份进程），检测目标库残余客户端连接。有未知连接则拒绝恢复；恢复失败
保持服务停止，验证通过后只恢复原来运行的服务，不顺带启动未启用资源池。

## 采集器契约

```text
CollectorSpec + CollectorRequest
             ↓
 fetch → transform/validate → store
             ↓
 CollectorResult + request evidence
```

- `CollectorSpec` 声明 API、业务表、主键、分页、空数据和资源类别。
- `CollectorRequest` 固化本次范围，运行中不可被调用方改变。
- `CollectorResult` 返回获取/写入行数、请求次数、空数据原因和证据。
- 通用采集器处理可参数化的稳定契约；专项采集器处理特殊分页、转换或多接口合并。
- 接口、采集器类、任务和业务表不是一一对应关系，数量只能从机器目录读取。

`tushare_raw_request` 始终保存脱敏参数、状态、行数和摘要；`tushare_raw_record` 仅保存
异常原文和历史存量归档。规范化错误与字段漂移分别进入专用错误表，不污染标准表。

## 重试、检查点与隔离

- 网络、超时、限流和数据库瞬时错误分类退避；参数、权限和契约错误不盲目重试。
- 网络、供应商瞬时错误、租约过期等终态由 Scheduler 在冷却窗口后按有限恢复轮次自动续跑；
  Dashboard 将其标为“等待上游”，而不是诱导人工反复点击。超过受控恢复预算后仍保留
  完整事件证据，供修复连接或任务定义后重新处理。
- Worker 使用租约和心跳；进程退出后实例可安全回收。
- acquire 节点保存请求级检查点，重试跳过已经验证完成的请求。
- 单个幂等采集请求遇到网络/超时，节点内最多尝试 3 次（退避 1、2 秒），
  每次短重试写入 transport_retry 事件；用尽后仍交给工作流有限恢复机制。
  限流、权限、参数、存储或完整性错误不适用该短重试，避免绕过配额与审计。
- `data_incomplete` / `completeness_guard` 不是简单重放验证：重试会从数据生产节点
  （采集任务的 `acquire`、派生任务的 `transform`）重新开始，并使下游节点回到 pending。
  旧 acquire 证据只能在最近一次数据节点重置之前追溯查看，不能被新的完整性验收复用。
  完整性失败的派生重试显式冻结 `reuse_existing_snapshot=false`，避免一直复用旧的
  partial 结果。复用已有快照仅适用于显式的发布对账，不是输入修复后的重新计算。
- 远程等待期间不持有数据库事务；批量 UPSERT 使用幂等主键。
- 所有 Worker 共享全局和接口级限流，并发不会绕过供应商额度。
- Financial Data 的单次协议载荷最多包含 100 个请求。全市场任务在同一个 acquire 节点内
  分批发送并汇总请求证据，不拆成子任务；该来源的定时任务还使用跨 Worker 串行领取门，
  防止多个独立实例同时消耗有限额度。HTTP 429 保留为 `rate_limited/waiting_upstream`，
  不冒充数据缺失，也不诱导操作员立即重复点击重试。
- `cyq_perf`、`index_weight` 作为配额保护任务按接口串行领取。
- `us_daily` 保留存量数据和查询契约，但当前研究范围不包含美股日线；任务定义、日常调度、
  初始化和缺口恢复均已停用，避免每小时一次的接口限制持续消耗额度。
- `cyq_chips`、ETF 成分和 `moneyflow_dc` 按周使用受控日期窗口采集，
  一个实体请求覆盖整周日频记录，避免按“证券 × 日期”重复调用。
- `cyq_chips` 的历史恢复按最近日期优先、每个实例不超过 31 个自然日推进；单个实例在
  acquire 内冻结全市场请求并可从检查点续跑，同一时间最多一个该任务实例。不得把 2018
  年以来的全部历史合并成一个请求，也不得一次创建数千个按日竞争额度的实例。
  Scheduler 每15分钟检查显式标记 `history_order=newest_first` 的窗口。只有执行成功且
  同一执行发布了覆盖整个窗口的 ready 状态，才创建前一段；通过前驱执行 ID 和幂等键
  保留接续关系，到2018-01-02停止。失败、未验证或活动窗口不会被跳过。
- `factor_value` 按交易日和受控因子列表采集；单因子跨多日可能达到上游 6,000 行截断，
  因而不能合并成周窗口。
- 错误终态保留为历史，通过 supersede 和新定义创建替代实例。

无日期的手工快照任务必须在 `frozen_scope.manual_parameters` 中显式保存参数；空对象表示
经过评审的全市场快照，不等于允许任意无界请求。这样 `fund_basic` 一类手工接口也能走
完整的 acquire、分页检查点、validate 和 publish 链路。

## 数据审计

### 因子历史批次的完成口径

已有快照不等于完成。批次跳过某个交易日必须同时满足当前公式版本、逐证券覆盖、
全部因子及技术指标审计为 ready 或有证据的 not_expected，以及 272 个抽检记录。
部分完成或未知状态不得计入 completed_dates；直接批处理分别返回 partial_dates，
命令行存在 partial 时返回非零退出码。抽检记录存在不表示与供应商数值完全一致。

财务同一报告主键的多行先按披露日期、更新标志、同版本非空字段数选择整行，
不能依赖分页返回顺序，也不能跨修订版本拼接字段。上游缺少财务字段仍保留缺口，
不能补零或自动沿用旧报告冒充当前报告数据。
资产负债表另存 fix_assets_total（固定资产合计）与 fixed_assets_disp（固定资产清理），
保留原始 fix_assets。三者不静默互相替代，缺少清理项也不推断其必为零。

`task_execution.status=success` 只表示工作流走完，不能证明数据完整。完整性由业务表、
请求证据、代码所有的审计规则和 `dataset_state` 共同决定。

| 审计模式 | 适用对象 | 完成证明 |
|---|---|---|
| `expected_partition` | 稳定发布的日/周/月/季度数据 | 应有分区、实体覆盖和传输证据 |
| `observed_scope_transport` | 稀疏事件数据 | 声明范围终态、分页穷尽且无未解决失败 |
| `exhaustive_snapshot` | 无日期快照 | 非空快照或供应商权威空结果及穷尽证据 |
| `dependency_scoped` | 派生数据 | 输入就绪且输出业务范围通过验证 |

数据状态包括 `pending`、`complete`、`empty_verified`、`gaps`、`partial` 和
`indeterminate`。只有精确范围请求成功、零行且证据可验证时，才能发布
`empty_verified`。

派生因子的 `ready` 与“公式运行结束”不是同义词。`local_factor_snapshot` 逐证券记录
`audit_status`、`calculation_status` 和缺失原因；只有适用范围内的证券通过输入、市场连续性
和公式审计后才计入严格 ready。停牌填充必须有逐日停牌证据；无法解释的行情断层保持
partial，不能通过放宽阈值或沿用旧值伪造成完整。

财报不是“每季度只采一次”。每天上海时间 18:20，
`v2_financial_disclosure_refresh` 为利润表、资产负债表、现金流量表、财务指标
刷新最近两个已结束报告期（最多 8 个有界实例，含周末披露）。业务范围仍是报告季度，
幂等键包含刷新日期；`force_acquire` 防止旧 complete 状态跳过新披露。
实际采集仍走原 V2 采集节点和独立校验，研究计算按公告日期过滤未来信息。
这不替代更早历史报表修订的专项补采。

全盘扫描只按当前规则版本生成修复建议。初始化也是“严格审计 → repair 实例 → 同一
采集与验证链 → 再审计”，不维护第二套采集器。

分区完整性无法证明响应中新增字段已经被重新获取。字段级 repair 必须冻结
`force_acquire=true`、`required_response_fields` 和修复原因，禁止被既有 complete 分区
提前跳过；验收同时检查 acquire 请求完成事件和字段级输入审计。尚未成熟的月/季度聚合
分区只会使预审计继续采集，不会在 condition 节点制造失败；采集后由有界请求的传输证据
验收本次精确范围。

`index_basic` 是发现目录，含不由 `index_daily` 发布的系列且没有统一失效日期，不能作为
指数日线的当日完整分母。`index_daily` 使用前后 14 日内最近 6 个已观测截面的最大值作为
基线，并保留 85% 阈值；漏掉一个 5,000 行分页会被检出，供应商支持范围变化不会制造
永久假缺口。若旧执行已保存分页穷尽证据而只因旧业务规则进入 attention，修订审计规则时
复用该传输证据，不重复调用供应商。

## Dashboard 语义

执行池隔离：`worker-v2-short` 是预留的日常短任务槽，领取时直接依据冻结的任务定义筛选
`daily`，并排除逐证券 `share_float`。整周成分、筹码等任务即使优先级更高也不能占用它。
`worker-v2-share-float` 独立处理解禁采集；`worker-v2-valuation` 独立处理指数估值分布，
不与全市场因子计算争用唯一的派生执行槽。新池不接管正在安全运行的旧池实例。

解禁日期与公告日期不同。上游拒绝未带证券代码的解禁日期窗口时，采集器在同一 acquire
节点内逐证券分页，保存已穷尽的证券断点及证券全集哈希。证券集合按上市/退市日期裁定，
不是东方财富候选名单；部分证券有数据不构成全市场完成。逐证券补历史在交易时间暂停，
保留断点且不消耗失败重试次数。

指数估值的交付对象是**同日有效样本分布**，不是每只成分都有数值。每个指标保留源 NULL、
非正值排除、有效数量和覆盖率；未知股息率不补零，源 NULL 不自动解释为亏损。
独立 SQL 核对样本数量、中位数、成员数量记账及业务范围；缺证券行、非有限值、成分异常
仍阻断发布。`meta.publication.full_numeric_coverage` 与任务完成状态分开。
严格输出审计直接复核当前行及公式版本，不能拿旧失败结论循环否定已修复的同一输出。

两融余额口径：`rzye` 为融资余额，`rqye` 为融券余额金额，`rzrqye` 为两者合计，
不能用融资余额冒充两融总额。大盘资金面默认展示合计，可切换三个口径，单位亿元；
个股原始字段单位元。大盘汇总必须包含当日应发布的交易所，不能把缺失交易所或空值填零。
`margin` / `margin_detail` 的余额质量规则同时检查三个余额非空、有限、非负及
合计恒等式（误差不超过 0.01 元）；分页完成、任务成功或证券数量达到阈值均不能绕过。
历史错误就绪证书以独立审计事件撤销，不篡改原执行记录。`invalid_balance_rows` 保存在
审计及日期分区证据中；全量身份清单可运行 `scripts/audit_margin_balances.py --output PATH`。
该清单只验证已存余额字段，不冒充全证券/全日期完整性证明。上游缺失金额时保留缺口，
不可将融券余量、估算市值或前收盘价推导值覆盖为供应商原始余额。
当 Tushare 复查仍不通过时，外部来源必须返回同一交易日、同一交易所证券的明确金额，
且与现有融资余额、融券余量等可用锚点相符。`margin_detail_repair_evidence` 按
`(trade_date, ts_code)` 保留修复前整行、采用的来源、采用值和请求证据。重放完全相同的
错误记录不会撤销修复；变化后的上游记录仍接受正常审计。交易所未列出证券不等于余额为零。
字段审计与证券全集验收分开报告；无同期标的名册或传输证据时，不将该日标为完整。

- 今日运营：业务日应执行的例行任务及交付验证；
- 采集任务：任务定义和内部节点；
- 执行实例：所有实例、节点事件、尝试和重试；
- 异常中心：尚未被后续成功状态覆盖的 attention；
- 数据日历：按 `observation_date` 展示数据状态，不按任务创建日期；
- 初始化：全量审计、修复和再次审计。

## 数据查询治理

标准数据查询默认只允许业务键和来源键。低选择性指标字段需要显式
`filter_mode=advanced`，并附带日期范围或至少一个标准业务键，防止无界全表扫描。

浅分页支持有限 `offset`；深分页使用绑定数据集和稳定排序列的不透明 `next_cursor`。
cursor 不可跨数据集复用，也不能与非零 offset 或总数扫描组合。

大型热表索引使用经审核的 `CREATE INDEX CONCURRENTLY` 迁移，在容量检查后显式发布。
发布后必须观察 `pg_stat_progress_create_index` 并用真实查询的
`EXPLAIN (ANALYZE, BUFFERS)` 验证，不能只看索引是否存在。

`scripts/diagnose_ebitda_bridge.py` 在一个只读、可重复读数据库快照中比较利润表、
现金流量表和财务指标，并保留快照 ID 与观测时间；避免采集刷新时跨版本拼接。
可通过 `--filing-facts` 传入多个原文抽取结果，在同一快照内重放组件解释。
`scripts/reconcile_filing_components.py` 也可独立重放，校验原始 PDF 字节哈希、
证券、报告期、公告日期、合并口径、单位和每一项基础组件，不只比较总额。

本轮核对发现三类不同机制，不能用统一修正系数消除差异：

- 比亚迪、沙河股份、中国建筑：现金流补充资料单列投资性房地产折旧摊销，
  不在原先四项 D&A 桥接中。
- 四川路桥：供应商固定资产折旧字段包含其他非流动资产摊销，财务指标 D&A
  没有包含这一项；不是可以继续相加的缺项。
- 双枪科技：原文利息收入负号与供应商利润表正号不同；指标 EBIT 对应按原文
  符号计算的算术结果。此证据解释差额，但不证明供应商的经济定义应被沿用。

五份 PDF 和 23 项组件证据保存在原始归档及同一治理报告目录；不写回供应商
业务表，不修改正式 EBITDA 公式，不把“解释了差异”当作逐日因子验收通过。
原始取数还有大量公告版本及三季报组件缺项，仍按未就绪处理。

字段级恢复在选择请求字段前先判断最新公告版本：即便较新证据只涉及另一字段，
也不能因列裁剪而重新使用旧版证明。只读取一个字段、跨公告截止日、冲突值和
缺少组件的行为均有回归测试，真实 PostgreSQL 用例使用独立测试证券并回滚。
