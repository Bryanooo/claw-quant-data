# 系统全貌与唯一口径

## 一句话定位

Claw Quant Data 是面向个人与研究 Agent 的可审计金融数据底座，负责多数据源接入、
任务执行、业务数据落库、完整性核验和研究数据服务。因子组合、策略回测、组合管理及
交易执行不属于本系统当前职责。

## 唯一机器口径

不要在文档里手工维护接口、数据集或来源数量。当前数字统一读取：

```http
GET /api/v1/system/overview
```

该接口只做跨层汇总，明细分别以下列接口为唯一来源：

| 问题 | 唯一明细接口 |
|---|---|
| 对外到底提供哪些服务 | `GET /api/v1/catalog` |
| 支持哪些研究方法、还缺什么 | `GET /api/v1/research/capabilities` |
| Tushare 与 蚂蚁数据源 如何分工 | `GET /api/v1/data/source-priorities` |
| 当前数据是否真的就绪 | `GET /api/v1/ops/data-health` |
| 系统的跨层摘要 | `GET /api/v1/system/overview` |

Dashboard 首页直接读取同一个总览接口，因此页面和 API 不再分别维护数字。

## 五层架构

1. **上游来源**：Tushare 批量历史与日常采集；蚂蚁数据源 按需补充；中国货币网
   等官方来源提供专属公开数据。
2. **数据生产**：版本化任务定义、执行实例、顺序节点、重试、租约和校验。
3. **规范数据**：PostgreSQL 业务表、统一代码/日期/单位、请求审计和数据集状态。
4. **研究服务**：基本面、技术面、宏观、行业、板块与事件 REST/CLI 契约。
5. **Agent 与 Skill**：只消费研究契约及质量证据，不直接理解供应商原始字段。

## 容易混淆的数字

| 名称 | 表达的对象 | 不代表什么 |
|---|---|---|
| 蚂蚁数据源 白名单路由 | 允许调用的供应商原始能力 | 不等于 Agent 研究接口 |
| 规范适配器就绪 | 已完成代码、日期、单位及字段映射的规范回退 | 不等于供应商全部能力 |
| 研究证据路由 | 已被研究服务治理后使用的供应商路由 | 不等于全部研究 REST 数量 |
| 对外研究接口 | 用户和 Agent 可以直接调用的稳定接口 | 不等于一个接口只依赖一个数据集 |
| 研究技术 | 系统宣称支持的分析方法 | 不等于 REST 路由数 |

因此，供应商路由、数据集、规范适配器、研究接口和研究方法必须分别统计，禁止再用
其中任意一个数字推导另一个数字。

## 数据选择规则

- Tushare 定时入库且审计通过的数据是确定性主口径。
- 蚂蚁数据源 只在明确的规范回退或研究证据契约中调用，不能覆盖本地事实。
- 供应商查询按路由分别标记 `available`、`empty` 和 `unavailable`。
- 蚂蚁数据源 原始响应不落库，只保存脱敏请求元数据；Agent 使用版本化的
  `provider_evidence.normalized`。
- 数据任务执行成功与数据集审计通过是两个独立状态，Dashboard 数据日历只展示后者。

## 补采与故障恢复口径

- 审计规则变更后，系统先发布新的任务定义版本，再淘汰仍在排队且审计契约过期的
  实例；旧实例及事件继续保留，真实缺口按新契约重新规划。
- 网络、上游瞬时故障、限流、数据库瞬时故障和租约过期会在冷却时间后自动恢复，
  但恢复轮次有上限；确定性契约错误不会被盲目重试。
- 同优先级补采按任务轮转领取，单个大型数据集不能独占全部 worker。
- `cyq_perf` 等配额受控数据集把多个缺失周期折叠为一个可续跑历史范围，同一时刻
  最多运行一个实例；已完成的上游请求通过事件检查点复用。
- 上游真实可用历史边界是审计契约的一部分。边界以前的周期属于“不应期待”，不会
  被统计为缺失，也不会生成补采任务。

## 当前产品边界

- 蚂蚁数据源 供应商均线的复权口径未明确时只作交叉验证。
- 尚未进入规范模型的供应商能力只能通过显式诊断网关调用，不能伪装成标准数据。
- 行业供需高频、Level-2、逐笔成交等仍需要新的合规数据源。
- 因子、回测与组合平台应建立在本系统研究与数据契约之上，作为独立系统演进。
