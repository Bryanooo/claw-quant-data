# V2 数据审计与就绪口径

## 权威口径

数据完整性以业务表、请求级传输证据、代码所有的审计规则和 `orchestration_v2.dataset_state` 为准。`task_execution.status=success` 不能单独证明数据完整。

每个公开数据集都有显式审计规则，规则包括：

- 逻辑周期与日期列；
- 上游可靠历史起点；
- 发布时间和宽限期；
- 是否需要交易日历；
- 是否检查点时实体覆盖率；
- 是否允许供应商权威空结果；
- 是否要求分页/范围穷尽证据；
- 规则版本。

规则由 Git 中的代码注册，任务定义发布时冻结其版本。运行规则与冻结契约漂移时阻断发布。

## 审计类型

| 模式 | 适用 | 完成证明 |
|---|---|---|
| `expected_partition` | 日/周/月/季度稳定发布数据 | 应有分区存在，必要时满足实体覆盖，并具有传输证据 |
| `observed_scope_transport` | 稀疏事件数据 | 声明范围有终态、分页穷尽且无未解决失败 |
| `exhaustive_snapshot` | 无日期快照 | 非空快照，或供应商权威空结果及穷尽证据 |
| `dependency_scoped` | 派生数据 | 所有输入就绪，输出范围通过业务校验 |

数据状态包括 `pending`、`complete`、`empty_verified`、`gaps`、`partial` 和 `indeterminate`。`empty_verified` 只在精确范围请求成功、返回 0 行且传输证据可验证时成立。

## 历史扫描与补采

全盘扫描对所有可审计数据集运行当前规则。只使用每个数据集、分区和规则版本的最新审计结果生成修复建议；旧规则的假缺口不会继续驱动补采。

修复遵守以下约束：

1. 一个 V2 repair 实例对应一个逻辑周期；
2. 上游可靠历史起点之前不生成实例；
3. 同任务、同周期存在活动实例时不重复创建；
4. 采集后由同一套独立审计复核；
5. 初始化只有在再次全量审计无问题时才为 `ready`。

## Dashboard 语义

- 今日运营：当前业务日应执行任务与验证结果；
- 执行实例：V2 全量实例及节点事件；
- 异常中心：仍未被替代成功覆盖的 `attention`；
- 数据日历：按数据的 `observation_date` 展示，不按任务创建日期；
- 初始化：全量审计、修复和再审计进度。

## 研究验收

研究接口还应通过 `scripts/validate_research.py` 的研究验证集。它验证研究问题到 API、数据集和底层表的穿透关系；研究验收不能替代底层审计，底层审计也不能证明某个研究结论正确。
