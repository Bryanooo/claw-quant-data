# 投资日历

投资日历用于回答“未来和当天有哪些可能影响研究判断的重要事件”。它与数据日历
是两个不同概念：

- **投资日历**展示宏观数据发布时间、央行事件和股指期货交割日；
- **数据日历**判断指定数据日期的业务数据是否已经完整落库并通过覆盖审计。

## 数据来源与真实性

| 事件 | 来源 | 日期口径 | 明细 |
|---|---|---|---|
| GDP、PMI、CPI、就业、央行等经济事件 | `eco_cal` / `tushare_norm_eco_cal` | 上游财经日历给出的事件日期和时间 | 国家、币种、前值、预测值、实际值 |
| 中金所股指期货交割日 | `fut_basic` / `tushare_current_fut_basic` | IF、IH、IC、IM 合约的 `last_ddate` | 合约代码、合约月份、最后交割日 |

系统不在浏览器中硬编码“每月第几个星期五”，也不把预测发布时间冒充实际发布。
经济事件只有在来源包含 `value` 时才标记为“已发布实际值”；事件时间已经过去但
`value` 尚为空时标记为“已发生、实际值待来源回填”，不能误报成“待发生”。尚未到
北京时间事件时刻才标记为“待发生”。同一事件的多次采集以最新来源版本展示。四类股指期货在同一交割日合并为一个日历事件，
明细仍保留所有真实合约。

## 重要性和类型

`eco_cal` 不提供稳定的重要性字段，因此系统使用可审计的关键词规则分类：GDP、PMI、
CPI/PPI、利率决议、非农、失业率、货币信贷、工业与消费、贸易等属于重要事件；
主要经济体的上述事件标记为 `high`，其他经济体标记为 `medium`。股指期货交割日固定
为 `high`。规则只用于筛选和视觉提示，不会改变上游日期、时间或数值。

控制台默认展示“核心事件”，可以切换为“全部重要事件”或“全部事件”，并按国家、
事件类型进一步筛选。

## API

查询一个月（单次最多 63 天）：

```bash
curl 'http://127.0.0.1:8000/api/v1/investment-calendar?start_date=2026-09-01&end_date=2026-09-30&importance=high'
```

查询指定日期：

```bash
curl 'http://127.0.0.1:8000/api/v1/investment-calendar/2026-09-18?importance=important'
```

可选参数：

- `importance=high|important|all`；
- `country=中国`；
- `event_type=growth|survey|inflation|employment|central_bank|money_credit|trade|housing|derivatives|speech|other`。

响应同时返回 `source_coverage`。控制台会明确显示财经日历已采集到的最早/最晚事件日
和来源更新时间；超过覆盖截止日不代表“没有事件”，而是尚无已采集事实。

## 未来事件采集

Scheduler 每日刷新以最近交易日为锚点的 `-7` 至 `+45` 天滚动窗口。实测 Tushare
`eco_cal` 单次最多返回 100 行，即使传入更大的 `limit` 仍保持该边界；接口支持标准
`offset` 且不同分页返回不同事件。因此采集器固定使用 100 行分页并一直请求到空页，
只有分页穷尽后任务才会标记为完整。断点保存在 PostgreSQL，Worker 重启后可以续跑。
