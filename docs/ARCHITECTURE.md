# 系统架构

## 定位与边界

Claw Quant Data 是面向个人研究和研究 Agent 的可审计金融数据底座，负责数据源接入、
任务执行、规范数据落库、完整性验证和研究数据服务。预测性因子、策略回测、组合管理和
交易执行由独立系统负责。

## 五层结构

1. **来源层**：Tushare 批量采集、蚂蚁数据源按需查询和已登记公开来源。
2. **生产层**：版本化任务定义、执行实例、节点、重试、租约和审计。
3. **规范层**：PostgreSQL 业务表，统一代码、日期、单位、主键和来源血缘。
4. **研究层**：基本面、技术面、宏观、行业、ETF 与事件的稳定 REST/CLI 契约。
5. **消费层**：Dashboard、个人研究工具和 Agent；不直接依赖供应商原始字段。

## API 分区

| 命名空间 | 作用 | 主要使用者 |
|---|---|---|
| `/api/v1/research/*` | 稳定研究对象、确定性计算和质量证据 | Agent、研究应用 |
| `/api/v1/data/*` | 规范数据集、来源目录和受控明细查询 | 数据工程、公式开发 |
| `/api/v1/ops/*` | 任务、实例、数据状态、初始化和健康检查 | Dashboard、运维 |
| `/api/v1/audit/*` | 请求证据、异常原文和血缘追溯 | 排障、审计 |

数据加工关系是“来源事实 → 规范数据 → 研究对象”；运营控制面不属于数据加工层。
统一服务目录由 `GET /api/v1/catalog` 提供，研究能力由
`GET /api/v1/research/capabilities` 提供。

## 状态与数量的唯一口径

文档不维护接口数、数据集数、队列数或缺口数。使用以下机器入口：

| 问题 | 权威入口 |
|---|---|
| 系统跨层摘要 | `GET /api/v1/system/overview` |
| 对外有哪些服务 | `GET /api/v1/catalog` |
| 研究能力与缺口 | `GET /api/v1/research/capabilities` |
| 数据源和优先级 | `GET /api/v1/data/sources`、`GET /api/v1/data/source-priorities` |
| 数据是否就绪 | `GET /api/v1/ops/data-health` |
| 任务和执行情况 | `GET /api/v1/ops/orchestration-v2/summary` |

供应商路由、采集接口、任务定义、执行实例、业务数据集、研究 REST 和研究方法是不同
对象，禁止由其中一个数量推导另一个数量。

## 数据选择规则

- 已经定时入库且审计通过的本地规范数据是主口径。
- 外部额度源只在明确的规范回退或研究证据契约中调用，不能覆盖本地事实。
- 供应商原始字段必须先经过代码、日期、单位和时点语义适配，才能成为规范数据。
- 任务执行成功与数据审计通过是两个状态；数据日历只展示数据状态。
- Agent 只依赖研究契约和质量证据，不直接拼接原始表或供应商响应。

## 面向 Factor Lab 的因子契约

claw-data 对 Factor Lab 提供统一的业务因子目录和值查询，不把供应商或内部计算服务
作为产品分类。Factor Lab 只看到稳定的 `factor_id`、版本、研究分类、资产范围、频率、
时点语义、质量状态，以及 `base` / `premium` 等级：

- `base` 只依赖标准行情、交易日历、复权、基础财务与估值等基础数据，可由已发布
  数据集稳定复算；
- `premium` 依赖受限数据包、较高额度或成本的数据、专项加工包，或需要单独验收和
  授权的增强数据。

`premium` 只表示使用门槛，不表示预测效果。等级作为因子版本元数据保存，不进入
`factor_id`。同一业务因子更换供应商或内部实现而数值口径不变时，Factor Lab 的身份
保持不变；公式、单位、时点语义或数值口径改变时必须发布新版本。

供应商、原始接口、请求参数、批次、额度成本、内部表、输入依赖、公式和程序哈希仍由
claw-data 完整保存。面向 Factor Lab 的数据集只携带不可变 `lineage_ref` 和内容哈希；
来源细节通过运维/审计入口反查，不进入研究者的因子选择与运行参数。

## 代码与数据安全

- 凭据只以 `env:VARIABLE_NAME` 引用，不写入任务定义、文档或响应。
- 数据库中的 handler 必须来自代码白名单，不动态执行数据库内 Python 源码。
- 审计事件追加保存；错误通过 supersede 和新实例纠正，不删除历史证据。
- 原始查询入口不是任意 SQL 或任意 URL 代理；过滤器、来源主机和返回范围均受白名单约束。
